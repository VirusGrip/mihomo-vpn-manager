# Mihomo VPN Manager

**Консольный менеджер прокси для Debian и Ubuntu:** импорт подписки, выбор сервера и настройка маршрутизации сайтов без графического интерфейса.

> **Статус: предварительная версия (beta).** Разбор ссылок и Python-код проверяются автоматическими тестами, но установка и работа со всеми вариантами подписок **не проверены на реальном сервере**. Сначала используйте тестовую виртуальную машину.

## Возможности

- Импорт **HTTPS-подписки** в формате Mihomo YAML (`proxies:`), списка ссылок или Base64-кодированного списка.
- Поддерживаемые типы узлов: **Trojan TLS, Hysteria2, VLESS (TCP / WebSocket / gRPC, в том числе Reality), Shadowsocks (SIP002)**.
- Выбор и смена активного узла из подписки.
- Добавление и удаление правил `DOMAIN-SUFFIX`, `DOMAIN`, `DOMAIN-KEYWORD`, `IP-CIDR` с действиями `VPN`, `DIRECT`, `REJECT`.
- Сохранение собственных правил при обновлении подписки вручную.
- Проверка синтаксиса конфигурации Mihomo перед применением, резервная копия и попытка отката при неудачном запуске.
- Служба systemd и локальный HTTP/SOCKS-прокси на `127.0.0.1:7890`.

**Важно:** это **не прозрачный системный VPN**. Прокси обрабатывает только приложения, настроенные на `127.0.0.1:7890`. Проект **не использует TUN, iptables и изменение таблицы маршрутизации**. Обычный трафик SSH, Docker и RustDesk не перенаправляется автоматически.

## Требования

- Debian 12/13 или Ubuntu Server с systemd и `apt`;
- архитектура `amd64` или `arm64`;
- права `root` / `sudo`;
- доступ к GitHub Releases и HTTPS-подписке;
- свободный TCP-порт `7890`;
- чистая тестовая установка **без существующего `/usr/local/bin/mihomo`, `/etc/mihomo/config.yaml` или службы `mihomo-manager.service`**.

Установщик **отказывается** работать при обнаружении существующей установки Mihomo, чтобы не повредить работающие сервисы. Миграция с действующего Mihomo пока не поддерживается.

## Установка

```bash
git clone https://github.com/USERNAME/mihomo-vpn-manager.git
cd mihomo-vpn-manager
sudo bash install.sh
sudo mihomo-manager
```

Замените `USERNAME` на владельца репозитория. Если `git` отсутствует: `sudo apt update && sudo apt install -y git`.

Установщик загружает последний релиз [MetaCubeX/mihomo](https://github.com/MetaCubeX/mihomo/releases), устанавливает Python 3 и PyYAML, создаёт службу `mihomo-manager.service` и включает её автозапуск. Служба запускается **только после импорта действительной подписки**.

## Первое подключение

1. Запустите `sudo mihomo-manager`.
2. Выберите **1 — добавить/заменить подписку**.
3. Вставьте **личную HTTPS-ссылку подписки** от вашего провайдера/3X-UI.
4. Выберите узел из найденного списка (например, Hysteria2 или Trojan).
5. Менеджер проверит YAML через `mihomo -t` и запустит службу.

Пример интерфейса:

```text
=== MIHOMO VPN MANAGER ===
Active: not configured
1. Add/replace subscription  2. Refresh subscription  3. Select VPN node
4. Add routing rule        5. Remove routing rule  6. Show rules
7. Show VPN nodes          8. Service status       9. Recent logs
10. Test proxy request     0. Exit
```

> Интерфейс программы в текущей версии — на английском, документация — на русском.

## Маршрутизация сайтов

По умолчанию через группу `VPN` направляются домены:

```text
openai.com
chatgpt.com
oaistatic.com
oaiusercontent.com
```

Остальные запросы, **поступившие в Mihomo**, направляются через `DIRECT`. Частные IPv4-подсети также `DIRECT`.

Для добавления сайта: пункт **4**, выберите тип правила, введите домен (`instagram.com`), затем действие `VPN`, `DIRECT` или `REJECT`. Для удаления — пункт **5**. Просмотр — **6**. Например, `DOMAIN-SUFFIX,instagram.com,VPN` включает домен и его поддомены, но для полноценной работы сервиса могут потребоваться дополнительные домены CDN/API.

**Порядок правил имеет значение.** Системные правила локальных адресов располагаются первыми, пользовательские правила — затем, `MATCH,DIRECT` — последним. Правила `IP-CIDR` не гарантируют обработку каждого обращения по доменному имени, если DNS-резолвинг выполняется вне Mihomo.

## Как использовать прокси в приложениях

```bash
# Проверка доступности прокси
curl -I -x http://127.0.0.1:7890 https://chatgpt.com

# Разовый запуск приложения с прокси
HTTPS_PROXY=http://127.0.0.1:7890 HTTP_PROXY=http://127.0.0.1:7890 codex
```

Прокси **не включается глобально для ОС**. Не задавайте переменные `HTTP_PROXY` и `HTTPS_PROXY` на весь сервер без необходимости.

> Проверка IP через `curl -x ... https://api.ipify.org` по умолчанию покажет **обычный IP сервера**, поскольку для этого домена действует `MATCH,DIRECT`. Это ожидаемое поведение. Для проверки маршрута конкретного домена смотрите журнал службы.

## Обновление подписки

Запустите `sudo mihomo-manager`, пункт **2**. Менеджер скачает подписку повторно и сохранит пользовательские правила. Если имя выбранного узла исчезло, предложит выбрать новый. **Автоматическое обновление по расписанию пока не реализовано.**

## Безопасность

- **Никогда не публикуйте настоящую ссылку подписки**: токен в URL обычно даёт доступ к вашим VPN-подключениям.
- Не добавляйте в Git файлы `/etc/mihomo/config.yaml`, `/etc/mihomo-manager/state.json`, реальные ключи, пароли или подписки.
- Прокси и API-контроллер Mihomo слушают только `127.0.0.1`.
- Конфигурация и состояние создаются с правами `0600`.
- При импорте используется HTTPS; редиректы на HTTP отклоняются.
- Установщик загружает бинарник с GitHub Releases **без криптографической проверки подписи/контрольной суммы**; для высокодоверенной среды нужна отдельная проверка поставки.
- Не запускайте установщик из непроверенных источников.

Если настоящая подписка случайно опубликована, перевыпустите её токен в панели провайдера.

## Ограничения

- Не все ссылки Xray/3X-UI совместимы с Mihomo. Некоторые параметры транспорта и расширенные форматы провайдеров не поддерживаются.
- Автоматический выбор самого быстрого узла и мониторинг доступности не реализованы.
- Успешная проверка `mihomo -t` и запуск systemd **не гарантируют**, что выбранный удалённый сервер отвечает.
- Внешние сервисы могут использовать дополнительные домены, которых нет в стандартных правилах.
- Нет автоматической миграции с уже работающего Mihomo.
- Конфигурация, импортированная из сторонней подписки, считается недоверенным вводом; используйте подписки только от доверенного провайдера.
